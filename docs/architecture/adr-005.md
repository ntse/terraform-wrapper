## ADR-005: Parallel Execution

**Status:** Accepted
**Date:** 2025-10-14
**Revised:** 2026-06-10

### Context

Sequential planning and applying of 20–30 stacks could cause CI jobs to exceed reasonable execution time.

### Decision

Implement parallel orchestration:

- Build a DAG from `dependencies.json` and execute independent layers concurrently (goroutines + WaitGroups).
- Limit concurrency with `--parallelism` (default: 4).

### Consequences

- Reduced plan/apply times in CI.
- Deterministic dependency-aware concurrency.
- Parallelization increases the need for global locking and clean logging.

### Superseded Behaviour

An earlier revision of this ADR also introduced per-stack plan caching
under `.terraform-wrapper/cache/<env>/<stack>/`, controlled via
`--cache` and `--force-plan` flags. Cache invalidation depended on hash
accuracy across input files, vars and dependencies, and frequently
produced stale plans when inputs changed in ways the hasher did not
observe (state drift, provider data sources, environment variables).
The caching layer was removed to restore predictable plan output; every
`plan` invocation now runs Terraform directly.
